# 신규 공급사 추가 범위

- 날짜: 2026-09-17
- 상태: 결정

## 논제

공급사를 코드에서 어떻게 식별하고 등록할 것인가. 공급사를 추가할 때 무엇을 고쳐야 하는가.

## 결론

- 공급사 식별은 enum이 아니라 문자열을 감싼 값 객체(`SupplierId`)로 둔다.
- 어댑터마다 자기 `SupplierId`를 들고 있고, 도메인은 어댑터 목록을 주입받아 순회한다. 공급사가 늘면 빈이 하나 늘 뿐이다.
- 설정에 없는 공급사나 중복된 ID는 기동 시점에 검증해 실패시킨다.
- 공급사별 설정 묶음: 기본 URL, API 키, 한 번에 보낼 코드 수(50), 타임아웃, 커넥션 풀 상한. 어댑터가 자기 것만 읽는다.
- "도메인 패키지가 어댑터 패키지를 import하지 않는다"를 ArchUnit 테스트로 고정한다.
- README에 신규 공급사 추가 체크리스트를 적는다: 패키지 생성 → 응답 객체·매퍼·어댑터 → 설정 추가 → Mock 추가 → 테스트. 도메인·검색 서비스·응답 계약은 건드리지 않는다.

## 근거

1. enum으로 두면 공급사를 추가할 때 도메인의 enum을 고쳐야 한다. "공급사를 추가해도 호출 쪽은 고치지 않는다"는 어댑터 계층의 전제와 부딪힌다.
2. 값 객체는 오타를 컴파일러가 잡지 못한다. 그래서 기동 시점 검증으로 대신한다.
3. 설계 문서에 적은 경계가 코드에서 유지되는지는 사람이 매번 확인하기 어렵다. 테스트 한두 개로 고정하는 비용이 작다.

## 논의 흐름

2. 사용자가 모두 타당하다고 보고 동의했다.
