## 4. 공급사 A와 B의 차이

| | Supplier A | Supplier B |
|---|---|---|
| 숙소 목록 | `GET /a/v1/hotels` | `GET /b/api/properties` |
| 재고·요금 | `GET /a/v1/availability?hotelCodes=` | `GET /b/api/search?propertyIds=` |
| 식별자 | `hotelCode` / `roomTypeCode` | `propertyId` / `roomId` (이름과 달리 객실 타입) |
| 요금 | **날짜별 1박 단가** `dailyRates[]` | **숙박 전체 총액** `totalPrice` |
| 세금 | **별도**: `nightlyRate`(세전) + `taxAmount` | **포함**, 세금액은 따로 안 줌 |
| 재고 | `dailyRates[].remainingRooms` | `inventory[].remainingRooms` |
| 실패 표현 | HTTP 4xx/5xx + `{error, message}` | **항상 HTTP 200** + `resultCode`, `data: null` |

두 공급사가 똑같이 따르는 규약:
- 인증은 `X-Api-Key` 헤더, 날짜는 `YYYY-MM-DD`, 체크아웃일은 숙박일에 포함되지 않음
- 재고·요금 조회는 한 번에 숙소 코드 최대 50개
- `maxOccupancy`는 성인+아동 합산이고, 공급사는 요청 인원을 수용하는 객실 타입만 반환
- 조식 포함 여부는 재고·요금 API에만 있음

예시 데이터로 검증할 수 있는 값:
- A `A-10023` Deluxe Twin: 132,000 + 165,000 + 132,000 = **429,000원**, 조식 미포함, 예약 가능 min(3,1,5) = **1실**

- A `A-10044` Namsan Garden Stay: 9/2 재고가 0이라 **예약 불가**
